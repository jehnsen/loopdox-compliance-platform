# Decisions

Choices made where the spec (`docs/spec.md`) was silent or where tooling forced a deviation. Newest milestone last.

## M1 — Foundation

### Tooling and versions

| #   | Decision                                                                                                                                                                                                              | Why                                                                                                                                                                                                                                                                                                  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | **TypeScript 6.0.3**, not 7.x.                                                                                                                                                                                        | `typescript-eslint` 8.71 supports `typescript <6.1`. Revisit when it supports TS 7.                                                                                                                                                                                                                  |
| D2  | **TanStack Table 8.21.3**, not 9.x.                                                                                                                                                                                   | The spec names v8.                                                                                                                                                                                                                                                                                   |
| D3  | **ESLint 9.39**, not 10.                                                                                                                                                                                              | ESLint 10 is new, and some plugins bundled by `eslint-config-next` don't declare support for it yet. 9.x is maintained.                                                                                                                                                                              |
| D4  | Request middleware is **`proxy.ts`**.                                                                                                                                                                                 | Next.js 16 renamed `middleware` to `proxy` (Node runtime).                                                                                                                                                                                                                                           |
| D5  | `typecheck` runs `next typegen && tsc --noEmit`.                                                                                                                                                                      | Pages use Next's generated `PageProps` / `LayoutProps` helpers, which only exist after typegen.                                                                                                                                                                                                      |
| D6  | shadcn/ui primitives are **vendored by hand** in `components/ui`, following shadcn's structure and APIs (`radix-ui`, `cva`, `data-slot`), and styled with our token names (`bg-surface`, `text-muted`, `bg-accent`…). | shadcn's generated classes use its own variable names (`bg-accent` = hover background, `text-muted-foreground`), which clash with this design system's names. shadcn's CSS variables are still defined in `globals.css` and mapped onto our tokens, so third-party shadcn snippets render correctly. |
| D7  | Dropdown menus default to **`modal={false}`**.                                                                                                                                                                        | Modal Radix menus set `aria-hidden` on a page that still has focusable elements, which fails axe's `aria-hidden-focus`. Escape and outside click still close them.                                                                                                                                   |

### Auth and BFF

| #   | Decision                                                                                                                                                                                                    | Why                                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| D8  | The **mock API issues real JWTs** (HS256 via `jose`) from `POST /auth/login`, and the BFF stores them in cookies exactly as it will for FastAPI.                                                            | The browser→BFF→backend code path is the same in mock and live mode, so going live doesn't change auth code.                             |
| D9  | Two httpOnly cookies: `${SESSION_COOKIE_NAME}` (access, `Max-Age` = token TTL − 30 s) and `${SESSION_COOKIE_NAME}_refresh`. A missing access cookie means "refresh now".                                    | No JWT decoding needed in the BFF.                                                                                                       |
| D10 | **Refresh happens in two places:** `proxy.ts` for page requests (so Server Components always get a valid token) and the `/api/v1` route handler for API calls (it also retries once after a backend `401`). | Server Components can't set cookies, so the refresh has to happen before rendering.                                                      |
| D11 | Cookies are `Secure` in production builds only.                                                                                                                                                             | Browsers treat `http://localhost` as secure, but dev servers reached over a LAN IP aren't, and Secure cookies would silently fail there. |
| D12 | **CSRF guard:** mutating `/api/*` requests must be same-origin (`Sec-Fetch-Site: same-origin`, or a matching `Origin`), on top of `SameSite=Lax`.                                                           | Defence in depth for cookie auth.                                                                                                        |
| D13 | `POST /auth/mock-login {email}` is a **mock-only** endpoint behind the "Sign in as…" list. It isn't in the FastAPI contract, and the BFF returns 404 for it in live mode.                                   | Lets the login page offer a one-click "Sign in as…" list without putting a password in client code.                                      |
| D14 | Every seeded user's password is `loopdox-demo` (mock only).                                                                                                                                                 | Lets the normal email/password form be tested too.                                                                                       |
| D15 | New passwords need **at least 12 characters**.                                                                                                                                                              | Unspecified; NIST-aligned minimum.                                                                                                       |
| D16 | Idle timeout: activity in any tab counts (shared over `BroadcastChannel`). After 30 min idle, "Still there?" counts down **60 s**, then signs out to `/login?reason=idle`.                                  | The spec says "dialog, then signs out" without a grace period.                                                                           |
| D17 | Non-members requesting `/orgs/:org/*` get **404**, the same as a missing org, not 403.                                                                                                                      | Org slugs can't be probed.                                                                                                               |
| D18 | Auditor guest memberships carry `expiresAt`. After it passes, the API returns 403 and `/me` stops listing the org.                                                                                          | Section 9.9 mentions guest expiry dates.                                                                                                 |

### Security headers

| #   | Decision                                                                                                                        | Why                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D19 | CSP is set per request in `proxy.ts`, with a **nonce for scripts** (`'strict-dynamic'`). `style-src` allows `'unsafe-inline'`.  | Radix positioning and progress bars use inline `style` attributes, which nonces can't cover. Scripts stay nonce-only, as the spec requires. `upgrade-insecure-requests` is only sent over HTTPS so local production builds over http keep working. |
| D20 | Static security headers (`X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`, `nosniff`) live in `next.config.ts`. | They don't vary per request.                                                                                                                                                                                                                       |

### API contract

| #   | Decision                                                                                                                                                                                                                                         | Why                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| D21 | `GET /me?org=:slug` selects the current tenant. Without `org`, `org` is filled in only when the user has exactly one membership.                                                                                                                 | Path-based tenancy: the slug is in the URL, not the token.                  |
| D22 | Added `POST /orgs/:org/notifications/read {ids}` or `{all: true}`.                                                                                                                                                                               | The bell needs to mark items read; the spec only lists `GET`.               |
| D23 | Search results are grouped by type, and snippets mark matches with `«…»`.                                                                                                                                                                        | The client highlights matches without trusting server HTML.                 |
| D24 | Errors use HTTP **405** with an `Allow` header for a known path with the wrong method.                                                                                                                                                           | Standard REST behaviour, in the same error envelope.                        |
| D25 | Ask cap on Starter: **100 questions per calendar month** in the tenant's timezone. Usage limits elsewhere (users: Starter 10, Pro 50, Premium unlimited; storage 1/10/100 GB; connectors 0/3/unlimited) are placeholders shown on the Plan page. | The spec's example meter reads "38 of 100". Other limits weren't specified. |

| #   | Decision                                                                                                                                                                                                                                           | Why                                                                                        |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |

## M2 — Policies

### Documents and workflow

| #   | Decision                                                                                                                                                                                                                                                                              | Why                                                                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| D39 | The five **section pages** are documents too (`SEC-001`…`SEC-005`), top level, with `requiresApproval: false`. Policies sit under them through `parentId`.                                                                                                                            | The spec calls them "section pages". Treating them as documents gives them bodies, history and links for free.                         |
| D40 | People without `policies.read_drafts` (staff, auditors) get a **projection** of each document: the approved version only, shown as Approved. Documents never approved, and retired ones, are invisible to them (404).                                                                 | Staff read the version in force. A draft after an approved version (ITD-015) must still show them v2.                                  |
| D41 | URLs use the internal document ID (`/policies/doc_itd_006`), which never changes. `GET /documents/:id` also accepts the human ID (`ITD-006`).                                                                                                                                         | The editor lets people change the document ID; links must survive that.                                                                |
| D42 | A **content change** (title or body) creates a new version. Metadata-only changes (owner, review cycle, classification, parent) don't. A content change returns an Approved or In review document to Draft; an In review document is withdrawn from review.                           | "Saving creates a new version" applies to content. Withdrawing from review keeps approvers from approving text that has since changed. |
| D43 | When `requiresApproval` is off, saving **publishes immediately**: the new version becomes the approved version, with the editor as `approvedBy`, and effective and review dates set.                                                                                                  | Overview pages shouldn't need a workflow.                                                                                              |
| D44 | **Retire** needs `policies.approve` (owner, admin, approver). Retired documents stay readable to editors and approvers, can't be edited, and have no review date.                                                                                                                     | Taking a policy out of force is an approval-level decision.                                                                            |
| D45 | **Delete** is allowed only for drafts that were never approved and have no child pages, behind a typed confirmation. Anything ever approved is retired instead.                                                                                                                       | Approved records are evidence and must be kept.                                                                                        |
| D46 | An approver **may approve their own submission**. ITD-001's sample text discourages it, but the app doesn't block it.                                                                                                                                                                 | Small organisations often have one admin. Self-approval is visible in the workflow and activity log.                                   |
| D47 | **Reordering** (drag or Move up/down) sets `parentId`/`order` without bumping `version`.                                                                                                                                                                                              | Order isn't content. Bumping `version` would turn every reorder into a 409 for anyone editing that page.                               |
| D48 | **Acknowledgement** is per approved version, and required from every active member with `policies.acknowledge` (everyone except auditor-only guests). It applies only to documents that require approval. Editors viewing a newer draft acknowledge from the approved version's page. | The approved version is the one in force.                                                                                              |
| D49 | The **Acknowledgements** and **Activity** tabs show only to people who can read drafts. The Controls tab shows to people with `evidence.read`, behind the Evidence plan gate.                                                                                                         | Activity mentions draft versions staff can't see.                                                                                      |
| D50 | Approving notifies the owner and everyone who must acknowledge. "Remind" notifies only people still pending. Submitting notifies approvers.                                                                                                                                           | Spec: notifications for approvals and acknowledgements.                                                                                |
| D51 | `GET /documents/next-id` suggests the next number for the most common prefix, ignoring `SEC`.                                                                                                                                                                                         | New policies default to ITD-017.                                                                                                       |

### Markdown, editor and diff

| #   | Decision                                                                                                                                                                                                                                | Why                                                                           |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| D55 | `[[ID]]` links show the ID inline, or "ID Title" when the link is the whole paragraph or list item. They always carry the title as a tooltip. Unknown IDs render as a red wavy-underlined span titled "No page with this ID yet". `[[ID | label]]` sets custom text.                                                    | Reads naturally in sentences and in "Related documents" lists. |
| D56 | Sanitising runs **before** `rehype-slug`, so heading IDs aren't prefixed. The TOC computes IDs with the same `github-slugger`, in the same order, and tests check they match.                                                           | Stable anchors for the TOC now, and for Ask citations (M7).                   |
| D57 | The edit page always refetches before showing the form, so `ifVersion` is current. Unsaved title and body are autosaved to `sessionStorage` per document; on return the editor offers to restore them.                                  | Fewer false conflicts; drafts never touch `localStorage`.                     |
| D58 | 409 dialog: "Review their changes" diffs their saved text against yours, "Overwrite with my changes" resends with their version number, and "Discard mine and reload" resets the form.                                                  | Spec: "Review their changes / Overwrite".                                     |
| D59 | DataTable columns are defined as display columns (`id` + `cell`), and sorting is server-side via `meta.sortKey`. Hidden columns and density persist (URL and cookie respectively).                                                      | Avoids `any` in TanStack's column generics; keeps every table view shareable. |
| D60 | Drag-and-drop in the tree places a page before or after another page, possibly in another section. Keyboard users get Move up / Move down in each item's menu. To move a page into an empty section, change Parent in the editor.       | Accessible reordering without a DnD library.                                  |
| D61 | Library layout toggle: "Tree and table" (default) or "Table only" (`?view=table`).                                                                                                                                                      | "Toggle tree/table".                                                          |
